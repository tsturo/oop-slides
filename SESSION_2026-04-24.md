## Live JS countdown — recipe

```html
<p id="deadline-countdown" style="font-size: 5.2rem; color: var(--accent); font-weight: 800; font-family: JetBrains Mono, monospace; text-shadow: 0 0 32px rgba(239, 68, 68, 0.55);">—</p>

<script>
(function() {
  // Vilnius is UTC+3 in late April (EEST). Deadline 23:59 EEST = 20:59 UTC.
  var deadline = new Date(Date.UTC(2026, 3, 26, 20, 59, 0));
  var el = document.getElementById('deadline-countdown');
  function pad(n) { return n < 10 ? '0' + n : '' + n; }
  function tick() {
    var diff = deadline - new Date();
    if (diff <= 0) { el.textContent = 'TIME IS UP'; return; }
    var totalH = Math.floor(diff / 3600000);
    var m = Math.floor((diff % 3600000) / 60000);
    var s = Math.floor((diff % 60000) / 1000);
    el.textContent = pad(totalH) + 'h ' + pad(m) + 'm ' + pad(s) + 's';
  }
  tick();
  setInterval(tick, 1000);
})();
</script>
```

# Updated build recipe (delta from GUIDE.md)

## Patterns that worked well this session

### Reveal cards (each card on its own click)

Reveal-slide CSS supports 3 steps. To make cards appear one-by-one, give each card the `reveal-block` class **directly**, no extra wrapper:

```html
<div class="slide reveal-slide">
  <h2>Title</h2>
  <div class="reveal-blocks" style="max-width: 880px; margin-top: 1.2rem;">
    <div class="reveal-block" style="margin-bottom: 0.8rem; background: var(--code-bg); border-left: 4px solid var(--accent); border-radius: 8px; padding: 0.9rem 1.2rem;">
      <p><strong>Question</strong></p>
      <p style="margin-top: 0.3rem;">Answer</p>
    </div>
    <!-- 2 more reveal-block elements -->
  </div>
</div>
```

Limit: 3 cards per slide. For more, split into multiple slides.

### Refactoring.guru images

- Section divider pattern: pattern hero image at `max-height: 340px; border-radius: 8px; background: white; padding: 10px;` (white padding handles cartoon backgrounds in dark mode).
- Real-world analogy slides: same idea but in two-col `.layout` with bullets/text on the left, image on the right.

### Equilateral SVG cycle (TDD)

For 3 nodes in an equilateral triangle:
- Same-Y baseline pair at `(120, 90)` and `(300, 90)` (180px apart)
- Third node at `(210, 246)` (height = 180 × √3/2 ≈ 156)
- All connecting arrow tangent points 70px apart
- ViewBox `0 0 420 310`

### SVG centering inside `.slide.center`

`width="100%"` collapses inside flex containers. Use **explicit pixel width + `max-width: 100%`**:

```html
<svg viewBox="0 0 600 160" width="900" style="max-width: 100%; height: auto; display: block; margin: 0 auto;">
```

### Title slide pattern variety preview

Don't list every pattern as tiny cards. Group into **3 big category cards** (Creational/Structural/Behavioral) for a stronger hero. Pedagogically consistent with the "Three Categories" slide.

### Animated SVG diagrams

Wrap SVG element groups in `<g class="anim-fade" style="animation-delay: Xs;">` and let `shared.css` animate fade-in on slide activation. For sequential reveal:

```html
<g class="anim-fade" style="animation-delay: 0.1s;">...</g>
<g class="anim-fade" style="animation-delay: 0.45s;">...</g>
<g class="anim-fade" style="animation-delay: 0.75s;">...</g>
```

### UML inheritance triangle

Hollow triangle pointing UP at the parent interface. Use a single tree-style connector for multiple subclasses:

```svg
<polygon points="400,170 390,185 410,185" fill="var(--code-bg)" stroke="var(--muted)"/>
<line x1="400" y1="185" x2="400" y2="205" stroke="var(--muted)"/>
<line x1="145" y1="205" x2="655" y2="205" stroke="var(--muted)"/>
<line x1="145" y1="205" x2="145" y2="225" stroke="var(--muted)"/>
<line x1="400" y1="205" x2="400" y2="225" stroke="var(--muted)"/>
<line x1="655" y1="205" x2="655" y2="225" stroke="var(--muted)"/>
```

### Quiz design

- Lead with **code-based** questions over definition recall
- 2-step reveal: first click shows options, second highlights correct + explanation
- Correct answer always wrapped in `<strong>` tag inside the `.col.quiz-answer.correct` div
- For end-of-lecture quizzes: show real-looking code (e.g. `LoggedReader` wrapping a reader → Decorator), avoid lambdas which obscure the pattern shape

## Pitfalls from this session

1. **Refactoring.guru images don't always match URL hints.** `live-example-en.png` for Facade is the phone-operator image, not the video converter. Check before mislabeling.

2. **Reveal-slide JS hardcodes 3 steps.** A reveal-slide with only 2 reveal-blocks still requires 3 right-arrow presses to advance (step-2 → step-3 no-op → advance).

3. **Image extension after `curl`** — refactoring.guru sometimes serves WebP under a `.png` URL. Run `file` and rename if needed.

4. **PreToolUse hook warnings about Read-before-Edit** are *advisory* — edits do go through. They fire even when the file is freshly read. Ignore unless an actual edit failure occurs.

5. **Playwright MCP visual review** stalled twice (~10-23 min) on long deck navigation. Static height inspection (counting code lines × line-height) was faster and equally effective.

6. **Triangle arrow tips** — the line should end at the *base* of the arrowhead triangle, not overshoot into the body. Compute the line `y2` to match the triangle's base coordinate.
